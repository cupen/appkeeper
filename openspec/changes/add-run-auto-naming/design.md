## Context

现行 `run` 的 ad-hoc 名称在守护进程的 `Supervisor::resolve_adhoc_name` 中解析：显式
`--app` 直接用，缺省取 `AdhocSpec.command` 的文件名 stem；随后 `cmd_adhoc_up` 先用
`adhoc_exists` 查重（`app_dir` 顶层与 `adhoc/` 记录、内存 `apps`、同名程序），命中即
409，唯一的改写入口是 `--force`。残留态（已启动未落盘）在查重之前用 `staged` 判定。
名称同时是单程序 app 的 app 名与程序名，并决定日志文件名
（`log_dir/<name>.out.log`）。

约束：

- 守护进程命令队列是唯一写者，名称解析、暂存与落盘必须在同一命令处理路径内串行完成；
- 注册记录分区（顶层 compose / `adhoc/` run 产物）与"程序名跨应用唯一"校验已存在，
  自动命名不得绕过这些关卡；
- 名称字符集由 `config::is_valid_name` 限定（`[A-Za-z0-9_-]`），`all` 为保留字；
- 日志文件按名字命名，名字复用会使新旧运行写进同一文件。

## Goals / Non-Goals

**Goals:**

- 未给 `--app` 的 `ak run` 在名称冲突时自动顺延出唯一名字，且行为可预测、可复现；
- 自动排重与既有残留确认、`--force`、显式 `--app`、跨应用程序名冲突的边界清晰；
- 选定名字回传客户端，脚本可稳定拿到（`program` + `auto_named`）。

**Non-Goals:**

- 不改变显式 `--app` 的同名拦截 / `--force` 语义；
- 不为自动命名引入持久化计数器或新的注册表文件；
- 不做名字清洗（非法字符、保留字仍拒绝），也不改变命令解析 / stem 提取规则；
- 不改变 `ak ps` 的展示结构与来源标注（自动命名的产物仍是 `run` 来源）。

## Decisions

### D1. 名称解析留在守护进程的命令处理路径

改 `Supervisor::resolve_adhoc_name`，缺省名从"取 stem"升级为"取 stem 后在占用集合中
找第一个空闲候选"。理由：命令队列串行，注册表记录、内存 app、程序名与暂存态可同源
判定，避免客户端预检与巡检/apply 竞态。

备选：CLI 先查 `ak ps --all` 再传名字——存在 TOCTOU，且离线语义/并发 run 会重名，
放弃。

### D2. 编号取「现存最大后缀 + 1」，不填中间空号

候选序列为 `base`、`base-1`、`base-2` …，跳过被占用的候选；后缀 N 取现有
`base-<k>` 中最大 k 加一（不存在时 1）。这与需求里"单调递增"一致，并让每次运行的
日志文件名（`log_dir/<name>.out.log`）不与已删除的中间编号混写。

备选：

- **最小空闲编号**：编号紧凑，但删掉 `npx-1` 后新进程会复用该名字并向旧日志追加，
  历史混淆；放弃。
- **随机短词后缀**：可读性好但不可预测，且与需求示意不符；放弃。

已删除的**最高**编号会被重新使用（无持久计数器）——这是不引入额外状态文件的代价，
写入 spec 作为已知边界。

### D3. 占用判定复用既有查重，扩展为三分态

抽出 `candidate_status(name) -> Free | Taken | Staged`：

- `Taken`：`adhoc_exists` 的既有判定（两处记录路径 lstat、内存 `apps`、同名程序）
  加上"其他应用已注册的同名程序"（原 `resolve_adhoc_name` 的冲突校验）；
- `Staged`：`state.staged` 中存在同名暂存 app；
- 其余为 `Free`。

循环遇到 `Free` 即采用；遇到 `Taken` 继续下一个候选；遇到 `Staged` **立即返回该候选**
（交给 `cmd_adhoc_up` 既有残留分支报残留），不静默跳过——否则会把"已启动未落盘"的
半完成注册藏起来并另起一个进程。

`--force` 且未给 `--app` 时不进入该循环，直接用 stem 作为覆盖目标（见 D4）；显式
`--app` 也不进入循环，沿用现有校验与 409/覆盖语义。

### D4. `--force` 未给 `--app` 时按基名覆盖，不参与排重

`--force` 的语义是"覆盖这个名字"。若它在缺省命名下也排重，顺延后名字必然空闲，
`--force` 会退化成空操作，与用户意图不符。因此：`--force` 存在时以 stem 为唯一目标，
有差异覆盖、无差异空操作。`--app` 显式给出时行为不变。

备选：`--force` + 无 `--app` 报用法错误——破坏既有脚本，放弃。

### D5. 非法/保留基名仍拒绝，不做清洗

stem 不是合法标识符、或等于 `all` 时，保持退出码 2 并提示 `--app`。自动排重只解决
"重名"，不负责把 `my.tool` 改写成 `my-tool` 或把 `all` 变成 `all-1`：静默改名会让
用户困惑，也会让命令与注册名对不上。

### D6. 结果回传 `auto_named`，客户端负责人类提示

`AdhocUpResult` 增加 `auto_named: bool`（发生后缀顺延时为 true），由 `/v1/run` 的
终端 NDJSON 帧透传；`--json` 输出包含该字段。人类可读输出在 `auto_named` 为 true 时
追加一行提示（如"自动命名：npx-1（基名 npx 已被占用）"），基名由客户端从已解析的
命令路径取 stem 得到，不额外占用协议字段。

备选：不加字段、只打印人类提示——脚本无法区分"用户指定的名字"与"自动顺延的名字"，
放弃。

### D7. 残留判定先于顺延

候选命中 `Staged` 时回传残留态（确认补落盘或放弃），保持"一次 run 只对应一个候选
名字"的直觉；顺延只用于已提交记录/内存态的占用。若基名已提交而 `base-1` 是残留，
同样报 `base-1` 的残留，让失败落盘尽早暴露。

## Risks / Trade-offs

- [默认行为变化：同名不再 409，而是静默创建 `name-1`] → 提案标记 BREAKING；README 与
  `--app` 帮助文案明确说明；依赖冲突检测的脚本显式传 `--app`。
- [最高编号删除后会复用，日志可能追加到旧运行文件] → 已知边界写入 spec/README；如需
  严格历史唯一，后续可引入轻量计数器状态，不属于本次范围。
- [名字数量随重复 run 增长，`ak ps` 出现 `npx-1…npx-100`] → 这是显式可见的代价；
  用户可用 `ak remove` 收敛；不自动清理运行中的历史注册。
- [占用判定漏掉某类名字会重名] → 判定集中在单个谓词，覆盖两处记录路径、内存 app、
  跨应用程序名与 staged；新增名字来源时必须同步该谓词（在 tasks 中列明单测矩阵）。
- [与检测/apply 的竞态] → 解析、暂存、落盘都在命令队列的单次处理内完成；检测合并
  不会在命令处理中途插入。

## Migration Plan

无需数据迁移：注册表结构与记录格式不变，已存在的自动/显式命名记录继续有效。回滚只需
恢复缺省命名分支；自动顺延产生的记录是普通 run 产物，可 `ak remove` 清理。

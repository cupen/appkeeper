# webui-ui Specification Delta

## ADDED Requirements

### Requirement: 程序操作菜单

控制台 SHALL 以单一「程序操作菜单」承载程序的 start / stop / restart 操作，供进程详情
与列表行两处复用（见「单程序控制」「列表行快捷操作」）。菜单 SHALL 满足：

- **双入口**：在程序行或进程详情页上右键，或点击 ⋯ 触发按钮（含键盘 Menu 键 / 触屏点按），
  打开同一菜单；MUST NOT 存在只属于某一入口的菜单项。
- **菜单项与状态匹配**：运行中（running/starting）提供 停止 / 重启，stopping 等过渡态
  不提供任何操作，其余状态提供 启动；菜单项 MUST 按当前状态启用/隐藏。
- **动作配色**：菜单项与内联确认按钮带动作色（启动绿 / 重启琥珀 / 停止红），色值用途边界
  见 `webui-visual-system`「操作动作的配色语义」。
- **二次确认**：启动为无损操作，选中即执行；停止 / 重启选中后 SHALL 在同一浮层内联变形为
  确认步骤（含程序名与带动作色的确认按钮），确认后才生效；取消或 Esc / 点击浮层外
  MUST 关闭确认且不产生任何状态变更。MUST NOT 使用浏览器系统弹窗。
- **可访问性**：菜单 MUST 可键盘操作（打开、方向键移动、Enter 触发、Esc 关闭并归还焦点），
  菜单项带可访问名称；打开期间菜单项按 `data-kind`（start/stop/restart）暴露给测试。
- **反馈**：操作结果 MUST 以可见反馈呈现（成功 / 失败原因），与操作入口表面无关。

#### Scenario: 右键与 ⋯ 打开同一菜单

- **WHEN** 用户分别通过右键程序行与点击行尾 ⋯ 按钮打开菜单
- **THEN** 两次呈现的是同一份菜单内容与状态（同一组件），菜单项集合由程序当前状态决定

#### Scenario: 启动免确认直接执行

- **WHEN** 用户在停止状态的程序菜单中选中「启动」
- **THEN** 菜单关闭、启动请求立即提交，不出现确认步骤

#### Scenario: 停止需内联确认

- **WHEN** 用户在菜单中选中「停止」
- **THEN** 同一浮层变形为「确认停止 <程序名>？」并呈现取消与带红色的确认按钮；点确认才提交，
  点取消 / Esc / 浮层外点击则关闭且程序状态不变

#### Scenario: 键盘完成整个操作

- **WHEN** 用户用键盘聚焦 ⋯ 触发按钮（或在行上按 Menu 键）、Enter 打开菜单、方向键选中
  「重启」、Enter 进入确认、再 Enter 确认
- **THEN** 重启请求提交，全程无需鼠标；Esc 在任一步关闭菜单并归还焦点

#### Scenario: 菜单操作失败有反馈

- **WHEN** 菜单发起的 stop 请求被后端拒绝
- **THEN** 界面展示失败原因，而不是静默无反应

## MODIFIED Requirements

### Requirement: 单程序控制

进程详情 SHALL 通过统一「程序操作菜单」对每个程序提供 stop 与 restart 操作，并对处于
非 running 状态且允许启动的程序提供 start 操作：详情页头部提供 ⋯ 触发按钮，页面任意处
右键亦可打开同一菜单（菜单语义、配色、确认与反馈见「程序操作菜单」）。破坏性操作
（stop / restart 运行中的程序）MUST 经菜单内联确认步骤后才会生效；start 选中即执行。
操作结果 MUST 以可见的反馈呈现（成功 / 失败原因）。进程详情页 MUST NOT 再渲染常驻的
start/stop/restart 按钮组。

#### Scenario: 重启运行中的程序

- **WHEN** 用户对 running 状态的程序经菜单选择 restart 并确认
- **THEN** 后端执行重启流程，界面上该程序状态经 backoff/starting 过渡后回到 running

#### Scenario: 停止操作需确认

- **WHEN** 用户经菜单选择运行中程序的 stop
- **THEN** 出现内联确认步骤；确认前不产生任何状态变更

#### Scenario: 操作失败有反馈

- **WHEN** 控制请求被后端拒绝（如程序已处于 fatal 且不允许 start）
- **THEN** 界面展示失败原因，而不是静默无反应

### Requirement: 列表行快捷操作

总览与 App 概况的程序行 SHALL 在鼠标悬停或键盘聚焦时，于行尾显现 ⋯ 触发按钮；点击 ⋯
或在行上右键 SHALL 打开统一「程序操作菜单」（语义见「程序操作菜单」），菜单项与当前
状态匹配（运行中提供 停止/重启，非运行且允许启动时提供 启动）。快捷操作区 MUST NOT
在悬停时推开或挤压同行其他列；行内 MUST NOT 再渲染常驻的 start/stop/restart 按钮组。
破坏性操作 MUST 经菜单内联确认后生效；操作结果 MUST 有可见反馈。

#### Scenario: 悬停出现操作

- **WHEN** 用户把指针移到运行中程序行上
- **THEN** 行尾出现 ⋯ 触发按钮，其他列位置不移动；点击后菜单提供 停止 与 重启

#### Scenario: 键盘可操作

- **WHEN** 用户用 Tab 聚焦到程序行的 ⋯ 按钮并触发
- **THEN** 菜单打开且可经键盘完成选中与确认，与鼠标路径一致

#### Scenario: 快捷操作失败有反馈

- **WHEN** 行内发起的 stop 请求被后端拒绝
- **THEN** 界面展示失败原因，不静默无反应

### Requirement: 日志查看

进程详情 SHALL 内嵌该程序 stdout 与 stderr 日志的查看器：默认展示文件末尾的
最新内容（tail），提供"跟随"开关（开启后持续追加新内容，关闭后停留在当前
视图），并提供暂停跟随时的手动刷新手段。日志 MUST 以等宽字体、保留换行的
只读文本呈现，stdout 与 stderr 可区分。

查看器 SHALL 提供日志配色档位选择器（位于查看器工具栏）：终端黑（缺省，黑底白字）、
纸面白（白底黑字）、米黄（护眼，`#F2EDDF` 底 `#4A4234` 字）三档，档位定义与
stderr 着色约束见 `webui-visual-system`「日志窗口配色档位」。所选档位 SHALL 经
浏览器本地存储持久化，缺省为终端黑；切换 MUST 即时生效，MUST NOT 跟随应用明暗主题。

日志区无输出时 MUST NOT 渲染任何等待类占位文案（如「等待输出…」）；工具栏的行数
计数不受影响。

#### Scenario: 查看最新日志

- **WHEN** 用户选中某程序查看其日志
- **THEN** 展示该日志文件的末尾片段，而非要求从文件头翻阅

#### Scenario: 跟随新输出

- **WHEN** 跟随开关开启且程序持续输出
- **THEN** 新日志行持续追加并保持视口贴近最新内容；用户向上翻阅历史时跟随应
  让位于浏览（不强行拉回底部）

#### Scenario: 缺省黑底白字

- **WHEN** 用户首次打开日志查看器（本地无历史选择）
- **THEN** 日志区以终端黑档呈现（黑底白字），无论应用当前处于明色或暗色主题

#### Scenario: 档位切换即时生效且持久

- **WHEN** 用户把档位从终端黑切到米黄，随后刷新页面
- **THEN** 切换即时生效且 stderr 行仍以红色系区分；刷新后仍为米黄档

#### Scenario: 空输出无占位文案

- **WHEN** 选中一个尚未产生任何输出的程序
- **THEN** 日志区不出现「等待输出…」等占位文案；工具栏行数计数显示 0

### Requirement: 品牌位版本号与关于对话框

控制台 SHALL 在左侧品牌位应用名下方以小号灰字显示当前守护进程的版本号（形如 `v0.1.0`），
与现有品牌小字同级；窄屏（≤720px）侧栏收为顶部条时 MAY 隐藏该行。品牌位 SHALL 是
控制台内版本号的唯一常驻展示位：页面级守护进程概况条 MUST NOT 再重复展示版本号。
用户双击版本号时 SHALL 打开「关于 appkeeper」对话框，展示版本号与构建元数据
（git 提交、构建时间、目标平台、Rust 版本），以及当前守护进程的控制端点、配置来源、
运行时长、应用数与程序数。对话框 MUST 可通过关闭按钮或 Esc 退出；版本位 MUST 可通过
键盘（Enter/Space）等价触发，且带可访问名称说明其用途。守护进程尚未提供投影时，
版本位 SHALL 显示占位符，对话框 SHALL 说明当前未连接，MUST NOT 渲染错误或空白字段。

#### Scenario: 侧栏显示版本号

- **WHEN** 控制台已连接守护进程且投影含版本 `0.1.0`
- **THEN** 品牌位应用名下方显示 `v0.1.0`，样式为小号灰字且不改变品牌行高

#### Scenario: 概况条不重复版本号

- **WHEN** 控制台已连接守护进程并渲染守护进程概况条
- **THEN** 概况条展示配置来源、运行时长、巡检、系统 CPU/内存与刷新控件，不含版本号；
  版本号只出现在品牌位

#### Scenario: 双击查看构建信息

- **WHEN** 用户双击品牌位版本号
- **THEN** 弹出对话框，显示版本号、git 提交、构建时间、目标平台、Rust 版本，以及控制端点、
  配置来源、运行时长与应用/程序数

#### Scenario: 键盘与关闭

- **WHEN** 用户用 Tab 聚焦版本号并按 Enter（或 Space），随后按 Esc
- **THEN** 对话框打开且焦点进入对话框；按 Esc 后对话框关闭且焦点回到版本位

#### Scenario: 离线占位

- **WHEN** 控制台从未取得守护进程投影
- **THEN** 版本位显示占位符，双击后对话框说明当前未连接，不显示伪造的版本或构建信息
